## Diffs from Spec's Assumed Defaults

### CRITICAL — Normalization formula wrong in spec for all four paths

The spec assumed `pixel/127.5 - 1.0` for both Det and Rec. Every path differs:

| Path | Actual | Spec assumption |
|---|---|---|
| Det ONNX | `(pixel/255 − mean_imagenet) / std_imagenet` per channel | `pixel/127.5 − 1.0` **WRONG** |
| Det RKNN2 | Raw uint8 0–255 (model normalizes via baked-in convert.py config) | `pixel/127.5 − 1.0` **WRONG** |
| Rec ONNX | `pixel / 255.0` | `pixel/127.5 − 1.0` **WRONG** |
| Rec RKNN2 | `pixel / 255.0` (must be done in calling code; not baked in) | `pixel/127.5 − 1.0` **WRONG** |

**Rust Task 3/5 impact:**
- `preprocess_det` (ocr.rs): apply `(v as f32 / 255.0 - mean[c]) / std[c]` per channel, not `/ 127.5 - 1.0`.
- `preprocess_det_nhwc` (ocr_rknn2.rs): just cast u8 to f32 with no division — the RKNN model handles normalization internally. Passing `/ 127.5 - 1.0` or `/ 255.0` would double-normalize and produce garbage output.
- `preprocess_rec` / `preprocess_rec_nhwc`: use `v as f32 / 255.0`, not `/ 127.5 - 1.0`.

### Det quantization defaults to i8 ON

The plan (Task 4) says "use FP16 for a baseline, no quantization." Det `convert.py` defaults to i8 (`DEFAULT_QUANT = True`). To get fp output you must pass `fp` as the dtype CLI arg. Rec is always fp (only `'fp'` is a valid dtype; no i8 option at all).

### DBPostProcess class defaults differ from demo config

Class constructor defaults: `box_thresh=0.7`, `unclip_ratio=2.0`. The demo `POSTPROCESS_CONFIG` overrides both: `box_thresh=0.6`, `unclip_ratio=1.5`. The spec's values are correct but they come from the demo config, not the class defaults. Any Rust code that hard-codes these should use 0.6 and 1.5.

### Trailing space must be appended to dict

The Rust `load_dict` helper in the plan reads lines from the file only. It must append `" "` to the returned `Vec&lt;String&gt;` (when the Rec postprocess is configured with `use_space_char=True`, which is the standard demo configuration), or index lookups for the space class will be off-by-one or silently mis-decode.

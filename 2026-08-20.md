**(a) No shared-backend concept exists today; it's spawn-per-invocation by design.** `apps/cli/src/args.ts` + `apps/cli/README.md`: every `dsh` invocation (`dsh web`, `dsh --profile &lt;tui-profile&gt;`, `dsh --profile headless`) is one OS process that composes a *complete* plugin tree from scratch — agent loop, session store, LLM adapters, everything — per `docs/architecture.md`'s "Profiles and bundles" model. `dsh web` = Host + webserver + built browser frontend **all in that one process**; there's an internal Client↔Host RPC split (`packages/api`), but both sides live in the same process/port. Nothing resembles "N frontends attach to 1 running agent backend."

**(b) The client/server split exists but for different purposes, not multi-GUI sharing:**
- `packages/sdk` (stdio JSON-RPC) is for *another process* driving a harness runtime it itself spawns (subagent-as-process, automation) — not for a GUI to attach to an already-running instance.
- `packages/api`/`dsh-client-connection`'s `WebApiClient` is the browser↔host RPC used *inside* one `dsh web` process.

So even the intended design has each surface (including a hypothetical Electron shell) embedding its own Host in-process via a different transport — not connecting out to one long-lived shared daemon.

**(c) The installed Desktop app's build pipeline is not in this repo.** Repo-wide search for `electron-builder`, `electron-forge`, "DSH Desktop", "dsh-desktop" returns nothing. ## 1. Mermaid 插件迁出重构：不合理，需要重做

- 未提交的改动（`ui-conversation/apply.ts`、`contract/slots.ts`、`ui-primitives/markdown/render.tsx` 等）只是把 `markdownFenceRenderers` 注册表和 `fenceRenderers` prop 接线加进了仓内代码——**没有创建任何独立包**，谈不上"迁出"。

## 2. 起 3 个实例：不是统一的设计缺陷，Desktop 是真正的问题点

- TUI 是终端内进程，一个终端一个进程本来就是所有 CLI 工具的模型，**不是缺陷**。
- `dsh web` 的 host 本来就支持多个浏览器标签页共用一个进程（浏览器端 cordis 树通过 HTTP/WS 连 host 端 cordis 树）——"共用一个"这件事在浏览器标签页之间已经是成立的。
- **Desktop 才是真问题**：它的 Electron 主进程自己内嵌启动了一整套独立 host，而不是去连接可能已经在跑的 `dsh web`。

**方案**（已写入 `.agents/notes/proposed/architecture/2026-08-20-shared-host-desktop-web.md`，含中文版）：加一个 `$DSH_HOME/web.lock` 发现文件（pid+端口，原子创建）；Desktop 启动时先探测，有活着的 host 就作为普通浏览器客户端连过去，没有才启动内嵌 host 并写锁；`dsh web` 启动时同样探测，发现已有 host（比如 Desktop 先起的）就复用而不是再绑 `:3080`。TUI 依旧保持独立，方案里明确写了这不是遗漏。

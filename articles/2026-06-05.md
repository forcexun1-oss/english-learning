# English Learning — 2026-06-05

Today's sessions continued **edge-agent** work: aligning phone and Rockchip stacks behind one HTTP interface, deploying **YOLO** on the RK1828 (I8), and hardening **LLM gateway** startup with HTTP-level tests after reboot.

## Vocabulary

- **uniform** – consistent across targets (*"the phone and the Rockchip should implement the same interface"*). Do not confuse with *uniformed* (wearing a uniform).
- **auto-start** – launch at boot; verify with *"The board has rebooted—verify both services start automatically."*
- **passthrough / wire in** – forward fields unchanged, or connect a script into startup (from yesterday's gateway work).
- **fp16** – half-precision model weights; *"Switch I8 to fp16"* after downloading the YOLO build.
- **localhost** – the device itself; apps call `localhost:8765` or gateway ports like `9091`.

## Grammar for Agent Instructions

| Rough | Better |
|-------|--------|
| *deloy yolo* | **deploy** yolo |
| *Swich I8 to fp16* | **Switch** I8 to fp16 |
| *I8 has beed deployed* | I8 has **been** deployed |
| *are the Mic , camera, LLM APIs uniformed?* | Are the **Mic, camera, and LLM APIs uniform**? |

When two hardware paths share one repo, **name the target first** (*"only the Rockchip perception-service chain"*). State test criteria explicitly—*"Test passed means the result is correct, not merely that the request went through"*—and ask for **HTTP verification** after deploy: *"Did you test via HTTP?"* For architecture pivots, use clear imperatives: *"Change the design: YOLO should run on the RK1828"* and *"Revert the code; YOLO and TTS both must run on the RK1828."*

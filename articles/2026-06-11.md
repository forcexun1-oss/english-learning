## Vocabulary

- **end-to-end (E2E)** – exercises the full HTTP path, not just “does it compile.”
- **smoke test** – a quick sanity-check binary; belongs in `smoke/`, not beside production binaries.
- **integration test** – crosses services; often in `tests/e2e/` while Rust unit tests stay next to source.
- **wrapper script** – one hook entry point when two hooks fire on every `UserPromptSubmit`.

## Grammar for Agent Instructions

| Rough | Better |
|-------|--------|
| *Is the test well agonized now?* | Is the test code **well organized** now? |
| *That make the structure unclear* | That **makes** the structure unclear |
| *I want you update the testing information* | I want you **to update** the testing information |
| *Englich coach message is disappeared* | **English** coach message **has** disappeared |

When restructuring a repo, name the boundary first: *Should all integration tests be placed in `tests/` and written in Python?* Before large refactors, ask the agent to restate the plan. For device work, be specific: *investigate why the service crashed* and *Will they kill the previously started service?*

## Vocabulary

- **materialize** – turn a repo reference into a real checkout; *materialize the embedded RK3576 rknn-llm repo into a working tree* is precise agent-speak.
- **side effects** – unintended changes elsewhere; pair risky edits with *Will this cause any side effects?*
- **end-to-end** – full pipeline, not isolated unit tests; *run all the tests end-to-end* but scope them (*most of the tests are not for the phone*).
- **latency** – response time in milliseconds; *request latencies* (not *latencys*).
- **prefill / KV cache** – LLM inference stages; ask *Does the prefill process run on the RK1828?* and *Is the KV cache stored in the RK3576?*
- **concisely** – short and clear; useful when requesting `pcie_upgrade_tool` from a vendor.

## Grammar for Agent Instructions

| Rough | Better |
|-------|--------|
| *could you genrate a weekly summery* | Could you **generate a weekly summary** |
| *complie and deploy* | **Compile** and deploy |
| *the flowing commands* | the **following** commands |
| *i has a problm with this commnd* | **I have a problem with this command** |
| *Can qwen3.5-9B be convert* | Can Qwen3.5-9B **be converted** |
| *Most of tests are not for the phone* | **Most of the** tests are not for the phone |

When asking vendors for binaries, state purpose and artifact: *Tell me the details of `pcie_upgrade_tool` so I can ask someone to provide it — how can I describe it concisely?* For hardware checks, name the device and metric: *What's the memory size of the RK1828 connected earlier? Reconnect the board and check.*

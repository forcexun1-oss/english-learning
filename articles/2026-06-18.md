# English Learning — 2026-06-18

Today's session focused on **parallel TTS and ASR work** on Rockchip boards: profiling CPU bottlenecks, running quality **gates**, and coordinating multiple coding agents through **git worktrees**.

## Vocabulary

- **gate** – a checkpoint that must pass before the next step; e.g. MeloTTS RKNN2 conversion failed its frontend gate because of dynamic operators (`NonZero`, `ScatterND`).
- **bake-off** – a side-by-side comparison of backends; you ran SenseVoice RKNN2 against baselines using **CER** (character error rate).
- **opt-in backend** – enabled only when configured (`asr_backend = "sensevoice-rknn2"`), not the default path.
- **worktree** – separate working directories for parallel agents editing the same repo without stepping on each other's commits.
- **frontend (ORT)** – the ONNX text-to-speech preprocessing stage; profiling showed `ORT.run` dominated latency on the RK3576 A72 CPU.
- **parity** – matching intermediate tensors between Rust and Python pipelines to find preprocessing bugs.

## Grammar for Agent Instructions

| Rough | Better |
|-------|--------|
| *this code dont work no matter what i try* | **This code doesn't work no matter what I try.** |
| *What's the memory usage? What's the execution flow? is it running on NPU/CPU?* | **What's the memory usage and execution flow? Is it running on the NPU or CPU?** |
| *commit changes* | Fine for agents; add scope when needed: **Commit the TTS profiling changes.** |

Use **doesn't** (not *dont*) in formal bug reports. Capitalize sentence starts and **I** when you mean yourself. When asking about hardware, name the board and unit: *RK3576 NPU* beats a bare *NPU/CPU*.

For blocked agents, numbered decisions work well: *Confirm option 1, then continue SenseVoice migration* gives clearer handoff than a vague *let him do it*.

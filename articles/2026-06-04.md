# English Learning — 2026-06-04

Today's session focused on **LLM gateway API redesign** for OpenAI compatibility, **port mapping** across phone and Rockchip targets (`8765`, `9091`, `80`), and **deploying** perception, ASR, and gateway services with HTTP-level verification.

## Vocabulary

- **OpenAI-compatible** – endpoints that follow `/v1/chat/completions`, standard roles, and fields like `finish_reason`.
- **passthrough** – forward a field unchanged (*"add finish_reason passthrough"*).
- **auto-start** – launch at boot (*"does the service auto-start"*); on Android you used **Termux:Boot**.
- **wire in** – connect a script or service into startup (*"check start-services.sh and wire them in"*).
- **localhost** – the device itself; apps call `localhost:8765`, not a remote IP.

## Grammar for Agent Instructions

| Rough | Better |
|-------|--------|
| *It work on 80 port* | *It **works** on port 80* |
| *write a API integration document* | *write **an** API integration document* |
| *are there defaut values* | *are there **default** values* |
| *How can I deloy qwen-asr* | *How can I **deploy** qwen-asr* |
| *are they did not started or crashed?* | *Did they **fail to start**, or did they **crash**?* |
| *does not the model version match* | *Doesn't the model version **match** the firmware?* |

When two hardware stacks share one repo, **name the target first**: phone vs Rockchip board. For API work, state the constraint clearly—*"re-design this API; require OpenAI compatible"*—and specify optional fields (*"session_id is optional; do not create session automatically"*). After deploy, ask for **HTTP tests**, not only build success: *"Test it via the HTTP API"* and *"What's the port number for localhost?"*

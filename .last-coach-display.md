## Research
Notes are in `docs/research/logging.md`; every claim is marked as backed by a source or as my inference.

| Idea | Decision | Why |
|---|---|---|
| Listen to `Application.logMessageReceivedThreaded` | Adopt | Captures every existing `Debug.Log("[tag] …")`, engine errors and `Update`/coroutine exceptions without changing console text. |
| Replace `Debug.unityLogger.logHandler` | Skip | It would change the console stream the bot scripts grep. |
| Unity Logging package (`com.unity.logging`) | Skip | Unity says it is for servers/Burst and "not a complete replacement" for `Debug.Log`. |
| Sentry SDK | Skip | Needs a server. I copied its ideas: 100 breadcrumbs, context on errors, screenshot attachment. |
| Sentry-style debounce (drop repeats) | Adapted | We count and summarise repeats instead, because the rate is the diagnosis. |
| Async writer with a capped queue | Adopt, changed | Serilog and NLog drop the arriving entry when full; we drop the oldest least severe entry, so Debug spam can never push out an Error. |
| Per-session rolling files with retention | Adopt | Scaled-down Serilog defaults: last 20 sessions, 200 MB total, 100 MB per session. |

What I couldn't find: an official Unity statement that the threaded log event runs on the logging thread itself (the no-duplicates guard depends on this; I confirmed it in a run instead), an official Epic page on log backups, and published studio conventions for how long to keep player logs.

## What was built
- **Pure logic** (`unity/Assets/Scripts/Core/Logging/`):
  - `Log.For("X")` with `Trace…Fatal`, cheap `IsEnabled` checks, optional exception and properties.
  - Levels from `AGENT_LOG_LEVEL`, e.g. `info,speech=trace`; default is Debug in the editor, Info in a build.
  - Parsing of the leading `[tag]` into a category.
  - Text and JSONL formats, the repeat counter, breadcrumbs, pluggable context providers, the capped queue, retention rules, and the background file writer.
- **Runtime** (`unity/Assets/Scripts/Game/Features/Logging/`):
  - Starts before the first scene loads.
  - Session files: `session-*.log` + `.jsonl` + `latest.log`.
  - Captures everything Unity logs, plus `AppDomain` unhandled and unobserved-task exceptions.
  - Session header and footer; warns at startup if the previous session closed uncleanly.
  - Detects a script reload during Play.
  - A `[GameModule(0)]` that adds game state to every error (phase, room, runs, boss, player hp, enemy count, `ctx.Paused`/`Running`, timeScale, `Juice` base scale, settings, module list) and records breadcrumbs.
  - Watches timeScale, frame spikes, and errors repeating every frame.
  - F8 bug-report bundle with screenshot, plus a throttled automatic mini-report on each new error.
  - `AGENT_LOG_SELFTEST=1`, kept as a documented debug tool.
- **Docs:** `docs/specs/logging.md`, a logging section and env vars in `CLAUDE.md`, and an entry in the docs index.

## Limits
- **Script reload during Play is untested.** Restarting the logger after a reload can't be triggered headless; it needs a real editor session.
- **Logging state is global.** `Log` is a deliberate global static, documented as the one exception to the no-singletons rule.
- **Screenshots miss the HUD.** They don't include IMGUI (HUD, pause menu), same as `ScreenshotTool`.
- **No remote upload.** Report folders are attached to bug reports by hand.
- **A native crash leaves no footer.** The next startup's warning is the only signal, and up to about 1 s of Info/Debug lines may be lost; Errors are flushed to disk immediately.
- **Secrets are only masked in the header.** Environment variables are masked by name; messages are not checked.
- **`.meta` files are now committed** for the new folders, unlike `BossIntro`, which has none.

### [MEDIUM] `CacheList.trim()` defeats the new surplus-mismatch check
**File:** `/Users/youxun/project/mlx-vlm/mlx_vlm/generate/dispatch.py:738-745`, against `/Users/youxun/project/mlx-vlm/mlx_vlm/models/cache.py:930-933`
**Confidence:** HIGH (code), MEDIUM (live reachability)
**Type:** correctness risk

`CacheList.trim` returns only the **last** sub-cache's trimmed count:
```python
def trim(self, n):
    for c in self.caches:
        m = c.trim(n)
    return m
```
The new check `if trimmed is not None and int(trimmed) != surplus` therefore cannot detect an under-trim in any non-last sub-cache. This matters because `CacheList.is_trimmable()` is `all(c.is_trimmable())`, and sub-caches with different clamps genuinely coexist: `ChunkedKVCache.trim` clamps to `offset - start_position` (cache.py:897), `PoolingCache.trim` clamps to `remainder` (cache.py:2209) while reporting `is_trimmable() == self.pooled is None`. `CacheList` is constructed in production paths (`apc.py:1766`, `apc_adapters.py:600/643/649`), so a `CacheList(chunked, pooling)` whose chunked half under-trims would pass the check and hand back a misaligned cache — the exact silent-corruption class the check exists to prevent.

Also: `SimpleKVCache` (cache.py:2674) has **no** `trim` method at all, and `CacheList.trim` raises `UnboundLocalError` on an empty `caches` list — neither is in the caught tuple `(AttributeError, TypeError, ValueError)` for the second case, so it would propagate out of `kvsession_plan` and fail the request. Both are pre-existing, not introduced here.

**Fix:** either compare per-sub-cache (`min` over sub-results is not enough — collect all and require every one to equal `surplus`), or, per the proposal's own instruction 「无法证明时停止并标 BLOCKED」, record `CacheList` as an unprovable case and reject `surplus &gt; 0` on any entry whose trim count cannot be individually attributed.

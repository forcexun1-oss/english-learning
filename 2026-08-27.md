### The specific serialization to remove

Staging happens in two phases that never overlap:

1. In `common_expert_cache::gpu_slab_stage_entries()` (common/expert-cache.cpp): the loop
   over misses reserves slots and accumulates pread tasks into `tasks`, and then
   `pread_pool_run(tasks)` runs **every** pread for **every** miss in that layer as one
   blocking phase. That is the 6.18 ms/token.
2. Later, at the MUL_MAT_ID node, `ggml_cuda_mul_mat_id_bindless()` calls
   `ggml_cuda_moe_slab_stage_experts()`, which issues the host-to-device copies. That is
   the 10.12 ms/token of copy engine time.

So an expert's bytes sit finished in the pinned host mirror while the other experts of the
same layer are still being read from the file, and no copy starts until all of them are
done.

**The task: start an expert's H2D as soon as its own pread completes**, so copies overlap
the remaining preads. The ceiling is min(6.18, 10.12) = 6.18 ms/token, which would take
28.74 to about 22.6 ms/token, roughly 44 t/s against 34.8 today.

### What this is NOT

Do not port the Metal shared-event machinery from `ggml-metal-device.m:719`. It solves a
different problem (encoding command buffers without blocking the CPU) and it cannot create
overlap here: layer L's expert set is unknown until layer L's router has run, and layer
L+1's router needs layer L's output, so there is no cross-layer work to hoist. The only
available overlap is pread against H2D within one layer's staging, which is what this cut
does. Do not touch `ggml_cuda_mul_mat_id_needs_sync()`; CUDA graphs stay disabled.

## Part A — derive the budget

Implement the derivation in `common/common.cpp`, immediately before the
`const bool use_expert_cache = ...` line at :1326. That is the right place because the
model is already loaded (so free VRAM reflects the weights) and `cparams.n_ctx` is in
scope, which the KV estimate needs. `common_expert_cache::init()` does not receive n_ctx
and should keep its current signature.

When `params.expert_cache_budget_auto` is set, compute:

    free VRAM after model load        (ggml_backend_dev_memory on the GPU device)
      - KV cache estimate for cparams.n_ctx
      - a graph/compute reserve
      = budget

Resolve the device the same way the cache does — see `common/expert-cache.cpp:2358`:
`ggml_backend_dev_by_type(GGML_BACKEND_DEVICE_TYPE_GPU)`, falling back to
`GGML_BACKEND_DEVICE_TYPE_IGPU`.

For the KV estimate use the public accessors in include/llama.h — `llama_model_n_layer`,
`llama_model_n_head_kv`, `llama_model_n_head`, `llama_model_n_embd` — as

    kv_bytes = n_ctx * n_layer * n_head_kv * (n_embd / n_head) * 2 * elt_size

where `elt_size` comes from `cparams.type_k` / `cparams.type_v` (use the larger of the two
if they differ, and `ggml_type_size` / `ggml_blck_size` to get bytes per element). If any
accessor returns a non-positive value, skip the KV term and say so in the log line rather
than computing a nonsense budget.

Graph/compute reserve: 512 MiB, overridable via `LLAMA_EXPERT_CACHE_AUTO_RESERVE_MIB`.

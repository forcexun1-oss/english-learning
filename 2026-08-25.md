## Why

cudaMemcpyAsync onto the dedicated MoE copy stream and then, at line ~470, records

completes**. The comment there says "All slot H2D work is ordered on this copy stream, so
this records the last copy enqueued for addr", which is true about ordering on that stream

Today that is safe only because the step is serialised: common_expert_cache::protect_step()

copy can still be pending when token N+1's eviction rewrites the same slot's pinned mirror.
The copy then moves the NEW bytes while the map records the OLD generation.

Note the two failure modes are different and both matter: the abort above is the loud one;
the quiet one is a later request for the old generation being skipped against a slot that
no longer holds it - silent wrong output, not a crash.

## What already exists, and what is missing

event, 0) before dispatching the indirect kernel. That gives **copy -> compute** ordering.

The missing direction is **compute -> reuse**: nothing stops eviction or a pinned-mirror
rewrite of a slot whose consuming kernel has not finished.

## The Metal reference (ggml-metal-device.m, roughly lines 655-760)

1. One process-wide `MTLSharedEvent` plus a serial `dispatch_queue_t` stage queue.
2. Reserve two monotonically increasing values: `ids_ready_value`, `staged_value`.
3. Pre-populate the bindless table with zeroed addresses so `table->buffer` exists.
4. End the current compute encoder, blit the routed ids from device memory into a shared
   `readback` buffer, then `encodeSignalEvent(ev, ids_ready_value)`.
5. `dispatch_async` onto the stage queue: wait for `ids_ready_value` on the CPU, call
   `ggml_moe_gpu_bindless_stage(...)` with the readback contents (that does the pread and
   the slab staging), request residency for the slab handles, report the timeline, then
   set `ev.signaledValue = staged_value`.
6. Back on the calling thread, `encodeWaitForEvent(ev, staged_value)` and recreate the
   compute encoder.

The essential property: the CPU never blocks. The command buffer is built with a GPU-side
wait on an event that a background CPU thread signals once staging is done.

## The hard part, which you must settle BEFORE writing the bulk of the code

Metal's `MTLSharedEvent` signals in **both** directions: GPU-to-CPU and CPU-to-GPU. The
CUDA runtime API has no direct equivalent. `cudaEvent_t` is recorded by GPU work only; the
host cannot signal one.

Candidate approaches, in no particular order:

- `cuStreamWaitValue32/64` + `cuStreamWriteValue32/64` (driver API). The closest true

  be justified.

  worker thread.

  staging at all. Stage layer L+1 while layer L computes, so the existing synchronous

## Execution flow inside gpu_slab_stage_entries(misses)

Called once per layer per token, with the misses for that layer. Roughly, in order:

1. Count how many slab slots the misses need.
2. **Eviction loop** (`while (!lru.empty() && ...)`): repeatedly walk the LRU backwards
   through an inner `do/while`, skipping any candidate found in `protected_keys`, then
   call `common_expert_cache_evict()` on the first unprotected one. Runs until enough
   bytes and free slots exist.
3. Per-miss loop: publish all-nocopy entries, `common_expert_cache_gpu_slab_reserve_slot()`
   for the rest, and build the pread task list (or, with CU2 enabled, do an L2-to-L1 copy).
4. `pread_pool_run(tasks)` (common/expert-cache.cpp:3165): hand the tasks to the parallel
   pread worker pool and wait for them.
5. CU2 finalize loop: mirror cold-miss L2 slots into their L1 slots. Inert here.
6. Publish residency and move entries to the LRU front.

## Execution flow: the loop being split

`gpu_slab_stage_entries()` runs the reserve-and-prepare loop once per miss. Per miss:

1. If every slice of the entry is `mmap_nocopy`, publish it as resident, move it to the
   LRU front, and skip the rest.
2. `common_expert_cache_gpu_slab_reserve_slot()` takes a free slab slot.
3. `common_expert_cache_gpu_slab_prepare_pread_tasks()` walks the entry's slices, writes
   the slot/buffer_index/slot_data_off metadata, and appends one pread task per slice.
   At its tail, when the packed slices do not fill the slot stride, it:
   a. calls `g_gpu_ops->slot_wait(...)` when bindless is on - a CUDA event query, and a
      `cudaEventSynchronize` if the event is not ready (added in ecd0ff4fe)
   b. `memset`s the remainder of the slot to zero, in the pinned host mirror
4. With CU2 enabled it would instead do L2 bookkeeping. CU2 is off in this configuration.

        slab-evict       0.235    ruled out: 1.000 LRU candidate per eviction
        slab-reserve    24.744    <- this loop, 59% of the decode
        slab-pread      12.478    ruled out: within 0.005 of the pread counter
        slab-finalize    0.150

24.7 ms/token over about 140 misses is roughly 0.18 ms per miss, which is a great deal for
taking a slot off a free list and appending two entries to a vector. Two candidates are
visible in the code, neither established:

- **The memset.** Every miss zero-fills `slot_stride - slot_off` bytes of pinned host
  memory. If the tail is large, or if `slot_off` is often near zero, the byte volume gets
  big quickly.
- **`slot_wait()`.** It is called per miss and can reach `cudaEventSynchronize`. Note it
  was added after the 22.6 ms figure was first measured, so it cannot be the original
  cause, but it can be adding to it now.

Do not assume either. Measure. Both being wrong again is a legitimate outcome; the
previous three cuts each disproved the hypotheses that motivated them.

## The API contract — phase 3 depends on this exactly

```js
window.transcript.apply(opsJSONString)   // Swift passes ONE JSON string; you JSON.parse it
```

`opsJSONString` parses to an array of ops, applied in order:

```
{ "op": "reset",     "messages": [Message, ...] }   replace everything
{ "op": "append",    "message": Message }           add one message at the end
{ "op": "update",    "id": "...", "segments": [Segment, ...] }  replace one message's content
{ "op": "remove",    "id": "..." }
{ "op": "streaming", "value": true|false }          show/hide the generating indicator
{ "op": "theme",     "dark": true|false }
```

```
Message = { "id": String, "role": "user"|"assistant"|"error", "segments": [Segment, ...] }

Segment =
  { "kind": "text",     "md": String }
  { "kind": "thinking", "md": String }
  { "kind": "tool",     "name": String, "input": String, "output": String,

  { "kind": "webHTML",  "html": String }
  { "kind": "webURL",   "url": String }
```

## Incremental update + selection protection (this is the point of the project)

- `update` must rebuild ONLY that message's subtree, not the whole list.
- Before rebuilding a message, check

  rebuild, mark the message deferred, and flush it once the selection collapses
  (listen for `selectionchange`). Otherwise streaming output constantly destroys
  a selection the user is making — which is the exact bug this whole migration
  exists to fix.
- Auto-scroll: before rendering, record

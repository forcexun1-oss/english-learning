## Three findings worth your attention

**1. `add_memory`'s content parameter is `episode_body`, not `content`.** I listed the live server's schemas rather than trusting the brief. Required params are `["name", "episode_body"]`; `group_id`, `source`, `source_description` are optional. Had I coded to `content`, every write would have failed validation.

**2. FastMCP double-wraps the payload — this changed the parser design.** The raw envelope is:
- `content[0].text` → the payload unwrapped: `{"message": ..., "facts": [...]}`
- `structuredContent` → **re-wrapped**: `{"result": {"message": ..., "facts": [...]}}`

My first draft preferred `structuredContent` and returned the nested shape, which would have pushed a `.result` hop into every caller. The client now parses the text block first and falls back to `structuredContent` (unwrapping a lone `result` key). Documented in the function comment so it isn't "simplified" back later.

**3. I moved the two default constants to `constants.ts`, with `client.ts` re-exporting them.** The spec has `config.ts` reading `DEFAULT_GRAPHITI_BASE_URL`/`DEFAULT_GRAPHITI_GROUP_ID`, but importing those from `client.ts` would pull the entire MCP SDK module graph into `loadConfig()` — i.e. into every session start, for all users, including the ~100% who have `graphitiEnabled: false`. The required export names still exist on `src/graphiti/client.ts` exactly as specified; only the definition site moved. Flagging it since it's a deliberate deviation from the written instruction.

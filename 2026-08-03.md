### Issues

**[CRITICAL] Cross-project ordering guarantee is broken — `pending.sort()` sorts by full path, not filename**
File: `mac-assistant/src/session_digest.rs:60` (the `pending.sort();` line inside `pending_sessions`, doc comment at lines 50-51)

`pending_sessions` collects `PathBuf`s from `discover_session_files`, which — per its own doc comment and the `discover_finds_jsonl_in_project_subdirs_and_skips_lock_and_sqlite` test — walks *all* project subdirectories under `sessions_dir` and returns full paths like `sessions_dir/--proj-a--/2026-...jsonl`. `Vec&lt;PathBuf&gt;::sort()` orders by full path (directory components first, filename last), not by filename. I verified this concretely:

```rust
let mut v = vec![
    PathBuf::from("/root/--proj-b--/2020-01-01_aaa.jsonl"), // older, proj-b
    PathBuf::from("/root/--proj-a--/2026-01-01_bbb.jsonl"), // newer, proj-a
];
v.sort();
// =&gt; --proj-a--/2026-01-01_bbb.jsonl   (first, despite being the NEWER session)
//    --proj-b--/2020-01-01_aaa.jsonl   (second, despite being the OLDER session)
```

Given the real directory shape from the brief ("holds one subdirectory per project"), this means: whichever project subdirectory sorts alphabetically first gets priority in every capped batch, regardless of actual session age. If that project keeps producing new sessions, an older, un-digested backlog in a later-sorted project directory is starved indefinitely — exactly the failure mode the brief's own doc comment claims this sort prevents ("升序保证被 cap 截断的批次每次都从最旧的开始推进，不会把老会话永远饿死"). That claim is false for the multi-project case.

Fix: sort by filename (or by stem), not by the full `PathBuf`:
```rust
pending.sort_by(|a, b| a.file_name().cmp(&amp;b.file_name()));
```
or extract `session_stem` for the sort key.

## Question
Multi-session (MS) accuracy swings ±20 points between re-ingests of the same questions. Where are the needed facts lost? For each failing MS question, every gold evidence statement must be traced through: source → graph → retrieval → answer.

## Inputs
- Dataset with gold: `datasets/longmemeval_oracle.json` (fields: question_id, question, answer, haystack_sessions; turns with `has_answer: true` are the evidence turns).
- Runs: `diag-ms-5` (12 MS questions) and `formal-graphiti-2` (MS questions only: question_type == 'multi-session'). Records: `results/pilot/<run>/records/graphiti/<case>/r*.json` (instance_key, qa.score). Failing question = mean score < 1.

- What the answering model saw: `results/pilot/<run>/evidence/<case>/r<k>/observability/events-*.ndjson`, event `graphiti.search_result` (data.returned[].fact — verbose level) and the prompt artifact under observability/artifacts (the user message holding `<graphiti-context>`); the final answer is the `agent.turn_end` text.

## Method (per failing question, per evidence turn with has_answer)
Classify each gold evidence item into exactly one stage where it was lost, quoting text:
1. **not_extracted** — no edge in the graph states it (search by salient tokens: numbers, proper nouns, key nouns; read the candidates; quote the closest fact if any).
2. **extracted_but_invalidated** — an edge states it but has invalid_at set (quote valid/invalid).
3. **in_graph_not_retrieved** — a correct edge exists but is absent from every repeat's search_result.returned.
4. **retrieved_but_answer_wrong** — it was in the returned facts / context the model saw, and the answer still mishandled it (quote the answer sentence).
Also record per question: number of evidence items, gold answer, the 3 answers (first 300 chars).

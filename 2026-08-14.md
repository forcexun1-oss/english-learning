=== TASK 2: stop evicting the most reusable node first ===

_enforce_memory_budget (around line 701) picks its victim as

a hit (in the warm-entry selection path). Prefill walks boundaries front to
back, so within one capture burst last_used ascends WITH depth, and none of
the new nodes has been hit yet. min(last_used) therefore selects the
shallowest node every time. Not a tie-break accident -- it is the ordering.

The shallowest node is the one to keep. It dominates on both axes: 10,153

=== THE DEFECT (verified in source, do not re-derive) ===

_seed_from_warm_snapshot (~line 800) scans every warm entry:

    for entry in self.warm_entries:
        rank = self._candidate_rank(prompt, entry.tokens)
        if rank[0] < self.min_prefix_tokens:
            continue
        if rank > best_rank:
            best = entry
            best_rank = rank
    ...
    slot.prefix_node = best
    best.last_used = time.monotonic()        # <-- only best

_candidate_rank (~line 857) returns (usable, -excess) with

    usable = lcp if excess == 0 or self._prompt_cache_is_trimmable() else 0

This model is untrimmable (qwen3.6: 30 linear_attention layers on
ArraysCache, can_trim_prompt_cache is unconditionally False), so usable > 0
means exactly "this node's tokens are a pure prefix of the prompt".

Measured consequence. Against a 19,198-token prompt the pool held nodes at
10,153 / 15,763 / 15,772 / 15,778 / 17,034 / 19,186 / 19,192. Every one of
the first six is a pure prefix of that prompt: all six were scanned, all six
scored as usable, all six were genuine candidates. Exactly one -- the
longest -- had its last_used refreshed. The other five got nothing.

So a shallow node is used by every request of that client shape and credited
on none of them. Its last_used stays frozen at the moment it was created,
while the deep winner is refreshed each time. _enforce_memory_budget then
picks min(last_used) and evicts precisely the node with the highest real
usage -- the one that is also the cheapest (260 MB vs 436 MB) and the only
one reusable across conversations rather than by a single repeated turn.

Credit every entry that qualified as a candidate, not only the winner.

The loop already computes `rank` for each entry, so the signal is free. Use
the same bar that admits a candidate at all -- rank[0] >= min_prefix_tokens
-- not `> 0`, and not "is a prefix", which would re-derive by hand something
_candidate_rank already decided.

Find every selection site, not just this one. At minimum there is the live
slot path in `select` (~line 774-790) and the disk tier

Two things to get right:

  - Cross-shape discrimination must survive. A node belonging to a different

    whether it needs a tighter condition there. Either answer is acceptable;

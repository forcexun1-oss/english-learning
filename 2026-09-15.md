<result>## Web Search Query Composition: Model vs. Server

Based on official Anthropic documentation, here's the precise distinction:

**What the Model Does (Client Responsibility):**
The LLM itself composes the search query string. When Claude decides to search, it emits a `server_tool_use` block with the query as the `input.query` parameter. From the [Web Search Tool documentation](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool.md), the response structure shows:
```json
{
  "type": "server_tool_use",
  "name": "web_search",
  "input": {
    "query": "claude shannon birth date"
  }
}
```
The model **alone** is responsible for formulating this query string based on the conversation context.

**What the Server Does (No Documented Rewriting):**
The [Web Search Tool documentation](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool.md) states: "The API runs the searches and provides Claude with the results." It describes what happens: Anthropic's servers execute the search against real-time indexes and return encrypted result content—but **there is no documented server-side query rewriting, expansion, or reformulation layer**. The query passes through as-is.

The documentation makes this clear under the "How tool use works" guide: web_search is a "server-executed tool" where "Anthropic runs the code." The execution is black-box to you (the developer), but the input contract is what matters: the model's `query` string goes in, search results come out, with no intermediate transformation mentioned.

**Bottom line:** The LLM optimizes; Anthropic executes. No automatic query rewriting happens server-side.</result>

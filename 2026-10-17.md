<result>## Bug Report

**Symptom**: Game-driven `pi --mode rpc` calls time out at 45s or return empty text. Alone, a call takes 6–12s and is often empty.

**Root cause**: Two parts, both measured.

1. **Hidden reasoning burns the whole token budget.** `models.json` declares `reasoning:false`, so pi sends no reasoning parameter. Ollama 0.40.5 then thinks by default (the reply carries a `reasoning` field), and `maxTokens` is 2048, so each call generates about 2048 tokens (6–12s). That thinking often eats the whole budget and leaves `content` empty. A direct request with `reasoning_effort:"none"` took 0.06s and returned "Hello!".
2. **Ollama serves one request at a time.** `OLLAMA_NUM_PARALLEL:1` is in the Ollama startup config logged at `/opt/homebrew/var/log/ollama.log`. Two pi processes therefore queue behind each other, and the 2-second kev call queues behind 10–25s generations. In the Ollama log, `/v1/chat/completions` entries show 16–25s during the earlier game run, and `/v1/systemone` shows `500 2.000s` (the game's 2s client timeout).

The `--session-id companion` process is the one that hits 45s. It queues behind the other process's back-to-back calls. With no kev traffic it still timed out 4 of 8 times, while the `--no-session` process never timed out.

**Reproduction**: `/private/tmp/claude-501/-Users-youxun-project-game-agent-roguelite/7cf6507c-b688-43d0-9e91-b78620dd6a1f/scratchpad/pi-repro/h.py`, driven by `run2.sh`, with output in `matrix2.txt`. I ran 8 calls per process against Ollama 0.40.5. No model was loaded at the start, and the `kev:9b-nvfp4` pull was left running.

**Evidence** (original config unless stated; "empty" = call finished with no text):

|---|---|---|---|---|
| 1 pi, no kev | 8 | 0 | 6 | 11.8s |

- With `reasoning:true` and `thinkingLevelMap.off:"none"`, pi sends `reasoning_effort:"none"` when `--thinking off`.
- `supportsDeveloperRole:false` is required. Without it, pi sends the system prompt as a developer message, the model's chat template rejects it ("System message must be at the beginning"), and every call fails after about 0.2s with an error.
- I did not test each field separately.
- I did not test serialising requests or a different model for kev. The reasoning fix alone removed the contention, since each call now takes under 0.5s.
- Lowering `maxTokens` alone would not help. The reasoning still runs and still leaves no text.
